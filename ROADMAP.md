## Adoption milestones

100,000 GitHub stars is an aspiration, not a release criterion or a promised
outcome. Track whether people can use and contribute to the product first.
These are proposed milestones; none is claimed as achieved.

1. **Publishable alpha:** deterministic gates pass, the chosen real-agent profile
   has retained artifact-bound evidence, and repository / npm ownership is confirmed.
   See [the launch checklist](LAUNCH_CHECKLIST.md) for the release source of truth.
2. **First 10 external trials:** record voluntary feedback on installation,
   time to the simulated demo, first real proof, failures, and repeat usage.
   Fix observed blockers before expanding the feature set.
3. **Repeatable onboarding:** a new user can follow the quickstart without help;
   publish a reproduction from retained real proof and clearly separate it from
   illustrative or simulated output.
4. **Contributor path:** at least one external adapter contribution passes the
   public contract and packed-package smoke; retain real compatibility evidence
   separately from contract tests.
5. **Broader adoption:** review stars alongside repeat users, usable proofs,
   issue resolution, and independent contributors. Choose outreach based on
   observed user value; do not represent downloads or stars as verified usage.

## Next — team change control

Only after the core loop is proven in public:

- policy-controlled promotion thresholds
- behavior lineage / supersession
- signed proof attestation / provenance identity
- community adapter gallery + compatibility evidence badges
- reusable deterministic Behavior Spec templates

## Later — broader harness change control

Potential future change surfaces:

```text
Rule
→ Memory
→ Skill
→ Tool policy
→ Workflow
→ Harness configuration
```

The invariant should remain:

> **No persistent behavior change without provenance, evaluation, and rollback.**

## What we deliberately will not become

- another general-purpose agent framework;
- another chat memory database;
- a prompt dashboard;
- a cloud requirement for local agent use;
- a rule-sync utility with no behavioral verification;
- an autonomous self-modifier that silently changes production behavior.
